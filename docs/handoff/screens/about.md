# 소개 `/about`

**읽는 화면이 아니라 확인하는 화면이다.** 30초 스크리너와 면접관 둘 다
「이 사람이 누구인가」를 확인하러 온다. 그래서 문서 톤보다 도구 톤에 가깝다.

공용 규칙은 `../README.md`.


### 구직 중 배지

옅은 초록 면 + 초록 텍스트 단계 + **기본색 초록 점 7px** · 라운드 9999 · 12px/500 ·
`padding: 6px 12px`.

**취업하면 바꿔야 하는 유일한 요소다.** 갱신하지 않으면 거짓이 된다 —
`지금 하는 일`처럼 자주 손대는 자리로 취급한다. 플래그 하나로 끄고 켤 수 있게 둔다.

### 히어로

```
프론트엔드로 시작해 [양쪽을 다 설명할 수 있는] 사람이 되려고 한다.
```
대괄호 부분만 `--devlog-blue`. 38 / 1.35 · −.035em · max 900.

### 행동 버튼 셋

`[메일 보내기]`(파랑 채움) `[이력서 PDF]`(기본) `[GitHub↗]`(기본)

**파랑 채움 예외 두 곳 중 하나다.** 근거: 스크리너의 최종 행동이 여기서 끝난다.
14px · `padding: 11px 20px` · 라운드 8 · 아이콘 18px.

**모바일에서 메일만 전폭인 이유**: 주 행동이다. 탭 하나로 연락이 되는 것이 이 화면의 목적이다.

### 연표

- 색 점 9px + 세로선 `1px border-emphasized`
- 마지막 항목은 세로선 없음
- 날짜 12px tabular-nums · 제목 15px/500 · 본문 14 / 1.65
- 항목 간 28 (모바일 24)
- 점 색은 최근 둘이 초록, 이전이 파랑, 시작이 `border-emphasized` — 기본색을 쓴다(글자 없음)

**모바일에서 날짜를 위로 올리는 이유**: 390px에서 82px 열을 빼면 내용 폭이 부족하다.

### 쓰는 기술

- 항목 — 아이콘 20px + 이름 13px · `1px solid border` · 라운드 8 · `padding: 10px 14px`
- **아이콘 색은 `secondary` 상속.** 브랜드 고유색을 쓰지 않는다
- 모바일 4열 격자 · 최소 높이 70 · 이름 11px 가운데 · `word-break: keep-all`

**실제로 프로젝트에 들어간 것만 적는다.** 이름을 아는 것과 쓴 것은 다르다.

**모바일에서 격자로 고정하는 이유**: 가로 흐름은 줄바꿈이 지저분해진다.
12개라 4·2·1 모두 나눠떨어지지만 `auto-fit`을 쓰지 않고 못 박는다.

## 어떻게 일하나 — 이 화면의 핵심

면접에서 자주 나오는 질문 셋을 미리 답한다. **지어낸 원칙이 아니라 실제로 지키고 있는 것들이다.**

| 질문 | 답의 핵심 문장 |
|---|---|
| 기술을 고를 때 무엇을 먼저 보나 | 기존 것으로는 왜 안 되는가에 먼저 답한다 |
| 혼자 만들 때 품질을 어떻게 지키나 | 규율 대신 도구로 강제한다 |
| 추상화는 언제 하나 | 두 번째 소비자가 생기기 전에는 안 한다 |

- 번호 배지 26px · 라운드 6 · **텍스트 단계 채움 + `on-fill`** · 파랑 → 초록 → 코럴
- 질문 `Heading level={3}` 21 / 19
- 답 17 / 1.75 `secondary` · **핵심 문장에 형광펜 + `hl-ink` 명시**
- 2번 답에 프로젝트 상세 「핵심 결정」으로 가는 링크 — 문서가 말한 연결을 실제 경로로

## 연락 — 버튼이 아니라 정보 카드

주소를 **모노스페이스로 그대로 노출**하고 아래 한 줄씩 맥락을 붙인다.

| 카드 | 주소 | 맥락 |
|---|---|---|
| 메일 | `hello@devlog.kr` | 평일에는 하루 안에 답한다 |
| GitHub↗ | `github.com/audemodo` | 저장소 여섯 · 커밋 1,318 |
| 글 구독 | `devlog.kr/rss.xml` | 새 글은 여기로 나간다 |

카드 호버는 공용 규칙(테두리 지우고 그림자 + `translateY(-2px)`).
