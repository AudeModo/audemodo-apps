# 대시보드 `/dashboard`

블로그를 만들면서 내가 보는 화면. **공개되지만 중심은 글 관리다.**
읽는 화면이 아니라 **훑는 화면**이다.

공용 규칙은 `../README.md`.

## 페이지 배경

**이 화면만 배경이 `--color-background-muted`다.** 다른 화면은 `body`.
흰 위젯 카드가 떠 있어야 벤토가 벤토로 보인다.

## 구조 — 벤토 그리드

```
[ 지금 하는 것 (2) ][ 할 일 ]
[ 손봐야 할 글 (2) ][ 갱신할 때 ]
[ 최근 커밋 + 잔디 (2) ][ PR·이슈 ]
[ 초안·글감 ][ 읽을거리 ][ 바로가기 ]
```

**중요도가 형태로 드러난다** — 두 위젯이 2칸, 나머지 일곱이 1칸.
벤토가 선형 스크롤의 단조로움을 깬다.

| | 데스크톱 (1144~) | 그 이하 |
|---|---|---|
| 격자 | 3열 · 2칸 span | **1열 스택** |
| 화면 제목 | 28 | 24 |
| 카드 패딩 | 20 | 18 |

`matchMedia`로 못 박는다. 위젯 아홉이라 `auto-fit`이면 고아가 생긴다.

## 조작 요소를 만들지 않는다

**데이터가 빌드 시점에 굳으므로 나도 남도 똑같이 못 누른다.**
안 그러면 고장난 것으로 오해받는다.

- **위젯 안에 체크박스 · 버튼 · 셀렉트가 없다.** 실측으로 0개여야 한다
- 할 일은 **완료 취소선 / 미완료 회색 원**으로만 표시
- 헤더에 `2026.08.08 04:12 빌드` — 왜 아무것도 안 움직이는지가 그 한 줄로 설명된다

**경계**: 이 규칙은 **위젯 내용**에 대한 것이다. 전역 크롬(네비 검색 · 플로팅)은
정상 동작한다. 모순이 아니다.

## 손봐야 할 글 — 핵심 위젯

네 칸(요약 · 분류 · 태그 · 썸네일)이 표처럼 정렬되어 빠진 것이 튀어나온다.

| 상태 | 글리프 | 색 |
|---|---|---|
| 채워짐 | `circle-check` | 초록 **텍스트 단계** |
| 빠짐 | `circle-x` | 코럴 **텍스트 단계** |
| 의심 | `alert-triangle` | 노랑 **텍스트 단계** |

흰 배경에서 기본색 초록은 2.99, 노랑은 1.9로 비텍스트 3:1에 미달한다 —
**글리프에는 텍스트 단계를 쓴다.**

깨진 링크도 여기 붙는다 — 글 제목 아래 `· 깨진 링크 2개`.

**모바일은 표가 안 들어간다.** 글마다 카드로 묶고 **라벨 붙은 배지를 나열**한다:
`✓요약 ✓분류 ⚠태그 ✓썸네일`. 표에서는 헤더가 알려주지만 카드에서는 배지마다 이름이 필요하다.
배지는 옅은 면 + 텍스트 단계 글자 · 라운드 6 · 11px/500.

데스크톱 격자: `1fr repeat(4, 34px) 54px` · 행 상단 `1px solid line-soft` ·
하단에 범례 세 개.

## 나머지 위젯

| 위젯 | 사양 |
|---|---|
| 지금 하는 것 | 프로젝트 · 학습 · 시리즈 · 읽는 중을 한 목록에. 종류는 **색 라벨**(텍스트 단계 11px/.1em)로 구분 |
| 할 일 | 완료 `circle-check-filled` 초록 + 취소선 `secondary` / 미완료 원 14px `1.5px solid border-emphasized` |
| 갱신할 때가 된 글 | 배지 — 지남 코럴 / 임박 노랑 / 여유 파랑 (옅은 면 + 텍스트 단계) |
| 최근 커밋 + 잔디 | 84칸 히트맵 + 레포별 최근 커밋 3줄 (모노 레포명 + 메시지 + 상대 표현) |
| 열린 PR · 이슈 | 오래된 순. `git-pull-request` 초록 / `alert-circle` 노랑. 23일 지난 것은 코럴 |
| 초안 · 글감 | `초안`(옅은 파랑) / `글감`(중립) 라벨 |
| 읽을거리 | 외부 링크 + `external-link` |
| 바로가기 | GitHub↗ · Analytics↗ · Vercel↗ · npm↗ · meta 문서(내부, ↗ 없음) |

**진행 표시가 갈린다**: 단계가 명확하면 **칸 막대**(M4 5단계 · 시리즈 6편),
비율만 알면 **연속 막대**(Spring 34장 · 책 22장).

**멈춘 시리즈를 따로 만들지 않는다.** 시리즈 항목에 `마지막 글 이후 N일`이
코럴로 뜨는 것으로 신호를 준다.

**조회수 · 유입을 넣지 않는다.** Analytics 바로가기로 대체한다.

## 이 화면 고유 계산

| 표시 | 계산 |
|---|---|
| 손봐야 할 글 | 프론트매터 신고 + 썸네일 유무는 글에서 직접 |
| 갱신 임박 | `lastReviewed` + `needsUpdate` 주기 → 남은 일수 → 지남/임박(45일 이내)/여유 |
| 시리즈 멈춘 일수 | 그 시리즈 마지막 글 날짜와 오늘의 차이 |
| 잔디 | 지난 12주(84일) 커밋 수 → 램프 4단계 |
| PR·이슈 경과일 | 생성일과 빌드 시각의 차이 |

## 데이터 출처 셋

| 출처 | 위젯 |
|---|---|
| MDX 프론트매터 | 손봐야 할 글 · 갱신할 때가 된 글 · 초안 |
| 정적 JSON | 지금 하는 것 · 할 일 · 글감 · 읽을거리 · 바로가기 |
| GitHub API (빌드 타임) | 열린 PR·이슈 · 최근 커밋 · 잔디 |

**JSON은 성격별로 나눈다.** 갱신 빈도가 다르다 — `바로가기`는 거의 안 바뀌는데
`할 일`은 자주 바뀐다. 한 파일이면 무엇을 고쳐도 전체가 다시 커밋된다.

**전환 경로**: JSON 스키마를 그대로 두면 서버가 붙을 때 **읽는 곳만 바뀐다.**
화면은 그대로이고 편집 UI만 얹으면 된다.
