# 프로젝트 상세 `/projects/[slug]`

**이 프로젝트에서 가장 중요한 화면이다.** 경계 강제 · 벤더 격리 · CI 게이트 같은 자산이
다른 화면에서는 안 보인다. 이 화면이 그것을 보여준다.

읽는 화면이 아니라 **보는 화면**이다. 표 · 막대 · 배지 같은 도구 요소를 쓴다.

공용 규칙은 `../README.md`.

## 구조 — 면을 여섯 번 교차

```
제목 36 + 상태 + 요약 + 스택 칩 + 링크 버튼
지표 4카드
───── 회색 ───── 푼 문제 + 아키텍처 도형
───────────── 핵심 결정 (3열 표)
───── 회색 ───── 마일스톤
───────────── 이 프로젝트로 쓴 글
```

## 레이아웃 매핑

| 요소 | 래퍼 | 데스크톱 | 모바일 |
|---|---|---|---|
| 제목 | `Heading level={1}` | 36 | 29 |
| 링크 버튼 | `HStack gap={2.5}` | 우측 정렬 | **전폭 2개** |
| 지표 | CSS grid | 4열 | **2×2** |
| 핵심 결정 | CSS grid | **3열 표** | **세로 카드** |
| 아키텍처 | `HStack` | 가로 흐름 | **세로 흐름** |
| 마일스톤 | `VStack gap={0}` + 행 구분선 | 동일 | 동일 |

지표 4카드는 `matchMedia` 분기로 열 수를 못 박는다 — `auto-fit`이면 3+1 고아가 생긴다.
모바일에서는 좁은 칸에 두 정보를 넣지 않는다: `커밋 · 2시간 전 마지막` → `커밋`.

## 핵심 결정 — 이 화면의 핵심

3열 표. **폭 비율 `1.15 : 1.35 : 1`.**

| 칸 | 폭 | 내용 |
|---|---|---|
| 결정 | 1.15fr | 무엇을 했나. 짧은 문장 15px/500 |
| 이유 | 1.35fr | 왜 그랬나. 14 / 1.7 `secondary` |
| 검증 | 1fr | **어떻게 확인했나.** 초록 배지 + 아이콘 + 아래 12.5px 한 줄 |

세 칸의 성격이 달라(짧은 결정 / 긴 이유 / 짧은 배지) 밀도가 무너지지 않는다.

**「무엇을 했나」만이 아니라 「얼마나 잘 했나」를 담는 자리다.**
검증 배지는 초록 텍스트 단계 채움 + `on-fill` 글자.

**모바일은 세로 카드.** 표에서는 헤더가 칸 이름을 알려주지만 카드에서는
각 구획에 라벨이 필요하다 — `결정` / `이유` / `검증`을 11px/.1em으로 붙인다.

## 아키텍처 도형 — 장식이 아니라 콘텐츠

```
apps/devlog     ┐
                ├─→ packages/design-system ─→ [벤더]
apps/dashboard  ┘
                   ↑ grep 0건 · CI가 강제
```

- 상자 — 모노스페이스 13px · 라운드 8 · `1px solid border`
- 래퍼 상자만 테두리 `text-primary`로 강조
- 벤더 상자는 **점선 + 회색 면** `secondary` 글자
- 화살표와 연결선은 `secondary` — **비활성색을 쓰지 않는다.** 의미를 나르는 요소다
- 초록 배지 「grep 0건 · CI가 강제」를 래퍼 아래에

**앱에서 벤더로 가는 화살표가 없다는 것이 이 도형의 내용이다.** 도형 아래 한 줄로 그렇게 적는다.

### 벤더 이름을 페이지에 리터럴로 심지 않는다

이 도형은 벤더 패키지명을 **보여주는 것이 목적**이라 화면에 그 문자열이 나온다.
리터럴로 적으면 저장소 전체 grep에 페이지 소스가 걸려 격리 검사가 무뎌진다.

래퍼가 내보내는 상수(또는 `package.json`의 의존성 이름)를 읽어 렌더한다:

```tsx
import { VENDOR_NAME } from '@audemodo/design-system';
// …
<DiagramBox variant="vendor">{VENDOR_NAME}</DiagramBox>
```

시안(`designs/devlog Project Detail.dc.html`)에는 리터럴로 적혀 있다 —
정적 HTML이라 상수를 읽을 수 없었다. **제품에서는 이 방식으로 바꾼다.**

| | 데스크톱 | 모바일 |
|---|---|---|
| 흐름 | 좌 → 우 | **위 → 아래** |
| 화살표 | `chevron-right` + 가로선 | `chevron-down` + 세로선 |

모바일의 세로 흐름이 오히려 직관적이다 — 의존 방향이 원래 세로다.

## 마일스톤

- 전체 진행 막대 8px · **파랑 → 초록 그라디언트** · `4 / 8`
- 상태 원 24px — 완료 초록 체크 / 진행 파랑 재생 / 예정 회색 숫자
  (완료·진행은 텍스트 단계 채움 + `on-fill` 글리프, 예정은 옅은 면 + 어두운 숫자)
- **진행 중 항목 안에 이중 막대** — `3 / 5 단계`. 전체 진행과 현재 단계를 동시에 본다

**있으면 렌더, 없으면 구간 자체를 생략한다.**
