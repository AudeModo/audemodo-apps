# P2 상태 카탈로그 — 라우트가 아니다

**부품이 무엇에 반응하는지**를 정한 문서다. 배포하지 않는다.

공용 규칙은 `../README.md` — 상태 규칙 본문은 거기 있다.

## 담고 있는 것

```
1장 반응 — 목록 행 3상태 · 카드 4상태 · 버튼 3단계 × 4상태
2장 기다림 — 로딩 스켈레톤 (로딩과 도착을 나란히)
3장 없음 — 빈 상태 · 404
```

## 이 시트의 방법 — 살아 있는 견본과 굳힌 견본

각 부품마다 **둘을 나란히** 둔다.

- **굳힌 견본** — 네 상태를 한눈에 비교하기 위해 상태를 고정한 것
- **살아 있는 견본** — 실제로 커서를 올리고 Tab을 눌러 확인하는 것

구현 검증에 그대로 쓸 수 있다. 굳힌 쪽과 살아 있는 쪽이 같아 보이면 맞는 것이다.

## 스켈레톤 — 이 시트의 핵심 측정

**로딩과 도착의 행 높이가 같아야 한다.** 시트에서 둘을 위아래로 놓고 실측했다:
썸네일이 정하는 **134px**로 양쪽이 일치한다.

- 면 `--devlog-track` · 반짝임 왼쪽에서 오른쪽으로 1.4s 무한
- 라운드 9999 (썸네일만 8)
- 감소 모션에서는 반짝이지 않고 면만 남는다
- 블록 높이는 최종 요소의 높이에서 나온다 — 제목 23 · 요약 14 두 줄 · 메타 12

**이 부품은 본문 8열(671) 이상에서만 쓴다.**

## 404 — 숫자는 보조다

```
404                              ← 44 · border-emphasized · aria-hidden
여기엔 아무것도 없다.              ← 26 / 22
주소가 바뀌었거나 아직 쓰지 않은 글이야.
[전체 글 보기]  [홈으로]          ← 강조 / 기본
```

**숫자를 44px로 둔다** — 홈 히어로와 같은 단계다. 스케일 밖 예외를 만들지 않는다.
메시지가 이미 404를 말하므로 숫자는 보조이고, 제목과 의미가 겹치므로 `aria-hidden`.

**강조는 「전체 글 보기」다.** 죽은 주소에서 살아남은 의도는 「글을 보러 왔다」이고
「홈으로」는 그것까지 버린다. 설명 문구가 이미 방문자를 글을 찾던 사람으로 단정하므로,
문구가 그렇게 말해놓고 버튼이 홈을 강조하면 화면이 자기 말과 어긋난다.
